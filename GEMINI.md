# AGENT GUIDELINES & PROJECT ANALYSIS: DOCTOR_HUNT

Welcome to **Doctor Hunt**! This document serves as the comprehensive system instructions and architectural guide for any AI Agent or developer working on this codebase.

---

## 1. Project Overview & Technology Stack

**Doctor Hunt** is a mobile application built with Flutter for doctor booking, appointment management, and medical search. It supports two user roles: **Patient** and **Admin**.

* **Language & SDK**: Dart `^3.12.2`, Flutter SDK
* **Architecture**: Feature-First Domain-Driven Clean Architecture
* **State Management**: `flutter_bloc` (^9.1.1) combined with `flutter_hooks` (^0.21.3)
* **Dependency Injection**: `get_it` (^9.2.1) + `injectable` (^3.0.0)
* **Routing**: `go_router` (^17.5.0) + `go_router_builder` (^4.4.0) using type-safe routes (`@TypedGoRoute`)
* **Localization**: `slang` (^4.19.0) + `slang_flutter` using JSON translation files (`assets/i18n/en.i18n.json`)
* **Backend & Services**: Firebase (`firebase_core`, `firebase_auth`, `cloud_firestore`, `google_sign_in`), Cloudinary (`cloudinary_api` for image uploads)
* **Storage**: `shared_preferences`, `flutter_secure_storage`
* **Error Handling & Functional Utilities**: `dartz` (`Either<Failure, T>`), `equatable`
* **Styling & Assets**: Google Fonts (`Rubik`), custom `AppColors`, generated `style_atoms.dart`, generated `app_assets.dart`
* **Testing**: `flutter_test`, `bloc_test`, `mocktail`

## 3. Mandatory Coding Rules & Conventions

### 3.1 State Management (BLoC + Flutter Hooks)
* **BLoC / Cubit**:
  * Business logic MUST be placed in BLoCs inside `presentation/controller/`.
  * All BLoCs MUST be annotated with `@injectable` or `@lazySingleton` for GetIt injection.
  * All Events and States MUST extend `Equatable` and implement `props`.
* **UI & Widget State**:
  * Screens SHOULD extend `HookWidget` from `flutter_hooks` to manage local UI controllers (e.g. `useTextEditingController()`, `useMemoized()`, `useRef()`).
  * Use `BlocBuilder`, `BlocListener`, or `BlocConsumer` to react to BLoC state changes.

### 3.2 Dependency Injection (GetIt + Injectable)
* **Annotations**:
  * Services/Datasources: `@lazySingleton` or `@injectable`.
  * Repositories: `@LazySingleton(as: AuthRepository)` or `@Injectable(as: DoctorRepository)`.
  * BLoCs: `@injectable`.
* **Initialization**: Dependency injection is configured in `lib/apps/core/di/di.dart`.
* **Rule**: NEVER instantiate dependencies manually inside BLoCs or UI screens; always retrieve them via `getIt<T>()` or inject them through BLoC constructors.

### 3.3 Routing & Navigation (GoRouter Builder)
* Routes are defined in `lib/apps/core/router/app_routes.dart` using type-safe `@TypedGoRoute`.
* Each route class extends `GoRouteData` and implements `build(BuildContext context, GoRouterState state)`.
* Route navigation MUST use the type-safe `.go(context)` or `.push(context)` methods generated by `go_router_builder` (e.g., `const AdminMainRoute().go(context)`).
* Unauthenticated vs Authenticated route guarding is centralized in `appRouter` inside `app_routes.dart`.

### 3.4 Localization (Slang i18n)
* **NO Hardcoded User-Visible Strings**: All UI text MUST be added to `assets/i18n/en.i18n.json`.
* Access localized strings using the global getter `t` (e.g., `t.create_doctor.title`, `t.admin.add_doctor_screen.enter_name`).
* Run `flutter pub run slang` or `flutter pub run build_runner build` whenever `en.i18n.json` is modified.

### 3.5 Error Handling & Functional Architecture
* Use `dartz` `Either<Failure, T>` for all Repository and UseCase return types (`Left(Failure)` vs `Right(T)`).
* Exceptions thrown at the service/datasource layer MUST extend `AppException` (e.g., `ServerException`, `NetworkException`).
* Repositories MUST catch `AppException` and map them to domain `Failure` instances (e.g., `ServerFailure`, `NetworkFailure`).
* UI/BLoC layers consume `Failure` and present user messages via `DialogUtils` or `SnackBarUtils`.

### 3.6 Styling, Typography & Assets
* **Colors**: Use `AppColors` constants defined in `lib/apps/core/theme/app_colors.dart`.
* **Typography**: Use the style atom extensions on `BuildContext` (e.g., `context.medium18.white.rubik`, `context.light16.textSecondary.rubik`).
* **Assets**: Use `AppAssets` for referencing asset paths (e.g., `AppAssets.imagesDoctor1`).

### 3.7 Data Backend (Firestore & Cloudinary)
* Use `FirestoreConstants` (`lib/apps/core/constants/firestore_constants.dart`) for Firestore collection names and field keys.
* Cloudinary file upload operations MUST go through `CloudinaryService`.

## 4. Code Generation & Build Commands

When adding or modifying routes, DI annotations, or translation keys, execute the code generation commands:

```bash
# 1. Run build_runner to generate DI (di.config.dart) and Router (app_routes.g.dart)
flutter pub run build_runner build --delete-conflicting-outputs

# 2. Run slang to generate localization files
flutter pub run slang

# 3. Generate asset paths (if assets changed)
flutter pub run flutter_assets_generator
```

## 5. Testing Guidelines

* Tests reside in `test/` mirroring the directory structure of `lib/`.
* **BLoC Testing**: Use `blocTest` from `bloc_test` package.
* **Mocking**: Use `mocktail` for creating mock repositories and services.
* Always verify initial state, loading state, success state, and error states for BLoCs.

## 6. Workflow Checklist for Agents Adding Features or Modifications

When assigned a task in this project, follow this exact workflow:

1. **Data Layer**:
   * Create/update Model or DTO.
   * Implement Service/Datasource with Firebase/Cloudinary calls using `FirestoreConstants`.
   * Define abstract Repository interface & concrete implementation with `Either<Failure, T>` return types. Annotate with `@Injectable(as: RepoInterface)`.
2. **Business Layer**:
   * Create Use Cases if needed.
   * Create BLoC, Events (`Equatable`), and States (`Equatable`). Annotate BLoC with `@injectable`.
3. **Routing & DI**:
   * Define route in `app_routes.dart` using `@TypedGoRoute`.
   * Run `flutter pub run build_runner build --delete-conflicting-outputs`.
4. **Localization**:
   * Add required translation keys to `assets/i18n/en.i18n.json`.
   * Run `flutter pub run slang`.
5. **Presentation Layer**:
   * Build screen extending `HookWidget`.
   * Use BLoC widgets (`BlocBuilder`, `BlocListener`) and style atoms (`context.medium18.white.rubik`).
   * Handle loading/error dialogs using `DialogUtils` and `SnackBarUtils`.
6. **Testing & Quality**:
   * Write unit tests for BLoCs and Repositories in `test/`.
   * Run `flutter test` to ensure zero regressions.
